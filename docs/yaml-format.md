# YAML Configuration Formats

Swift supports two YAML formats for creating VMs and networks:

1. **Simplified format** — human-friendly key-value pairs
2. **XML-mirroring format** — lossless 1:1 mapping of libvirt XML

## Simplified YAML format

### VM configuration

```yaml
name: myvm
disk: /path/to/ubuntu-22.04.qcow2
memory: 2048          # MiB
cpu: 4
storage: 20G          # disk size
username: ubuntu
password: mypassword
ssh_key: ssh-ed25519 AAAA...
graphics: vnc         # spice, vnc, or none
websocket: true
serial: true
networks:
  - name: default
    model: e1000
  - name: mynet
    model: virtio
```

#### Fields

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `name` | string | (required) | VM name |
| `disk` | string | (required) | Path to cloud image backing file |
| `memory` | uint | 512 | Memory in MiB |
| `cpu` | uint | 1 | Number of CPUs |
| `storage` | string | 8G | Disk size (supports G, M, T suffixes) |
| `username` | string | swift | Cloud-init username |
| `password` | string | swift1234 | VM password |
| `ssh_key` | string | | SSH public key |
| `graphics` | string | spice | Graphics type: spice, vnc, none |
| `websocket` | bool | false | Enable WebSocket for browser console |
| `serial` | bool | false | Add PTY serial console |
| `networks` | list | | Network attachments |

### Network configuration

```yaml
name: mynet
cidr: 192.168.100.0/24
mode: nat
dhcp: true
dhcp_start: 192.168.100.100
dhcp_end: 192.168.100.200
```

#### Fields

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `name` | string | (required) | Network name |
| `cidr` | string | (required) | CIDR notation (e.g. 192.168.100.0/24) |
| `mode` | string | nat | Forward mode: nat, isolated, route, bridge |
| `bridge` | string | | Bridge device name (bridge mode only) |
| `device` | string | | Host device for forwarding |
| `dhcp` | bool | false | Enable DHCP |
| `dhcp_start` | string | | DHCP range start IP |
| `dhcp_end` | string | | DHCP range end IP |

### Usage

```bash
# Create VM from simplified YAML
swift create myvm -f vm.yaml

# Create network from simplified YAML
swift network create mynet -f network.yaml

# Flags override YAML values
swift create myvm -f vm.yaml -m 4096 --cpu 8
```

## XML-mirroring YAML format

This is a lossless representation of the full libvirt XML definition. Generated by `swift show -o yaml` and `swift network show -o yaml`. Can be edited and fed back to `swift create -f` / `swift network create -f`.

### Conventions

| XML construct | YAML representation |
|---------------|---------------------|
| `<element attr="val">` | `element: { '@attr': val }` |
| `<element>text</element>` | `element: text` |
| `<element>text</element>` with attr | `element: { '@attr': val, _: text }` |
| `<element/>` (empty) | `element: null` |
| Multiple `<element>` children | `element: [ {...}, {...} ]` |

### Example: VM definition

```yaml
domain:
    '@type': kvm
    name: myvm
    uuid: 0da02ace-0af8-428f-b6d8-adf0734be39e
    memory:
        '@unit': KiB
        _: "524288"
    currentMemory:
        '@unit': KiB
        _: "524288"
    vcpu:
        '@placement': static
        _: "1"
    os:
        type:
            '@arch': x86_64
            '@machine': pc-i440fx-6.2
            _: hvm
        boot:
            '@dev': hd
    devices:
        disk:
            '@device': disk
            '@type': file
            driver:
                '@name': qemu
                '@type': qcow2
            source:
                '@file': /var/swift/myvm/myvm.qcow2
            target:
                '@bus': virtio
                '@dev': vda
        graphics:
            '@type': spice
            '@autoport': "yes"
        interface:
            '@type': network
            mac:
                '@address': 52:54:00:aa:bb:cc
            model:
                '@type': e1000
            source:
                '@network': default
```

### Example: Network definition

```yaml
network:
    name: mynet
    forward:
        '@mode': nat
    bridge:
        '@name': virbr1
        '@stp': "on"
        '@delay': "0"
    ip:
        '@address': 192.168.100.1
        '@netmask': 255.255.255.0
        dhcp:
            range:
                '@start': 192.168.100.2
                '@end': 192.168.100.254
```

### Usage

```bash
# Export current VM definition as YAML
swift show myvm -o yaml > myvm.yaml

# Edit the YAML
vim myvm.yaml

# Recreate from edited YAML
swift create -f myvm.yaml

# One-liner round-trip
swift create -f <(swift show myvm -o yaml)
```

### Differences from simplified format

| Aspect | Simplified | XML-mirroring |
|--------|-----------|---------------|
| Fields | Flat key-value | Nested, mirrors XML |
| Attributes | Not supported | `@` prefix |
| Text content | Direct value | `_` key |
| Completeness | Partial (common fields) | Full libvirt definition |
| Provisioning | Creates disk + cloud-init | Requires files to exist |
| Flags | Can override YAML values | Flags are ignored |

### Important notes

- The XML-mirroring format **does not** create disk images or cloud-init ISOs. The files referenced in the definition must already exist on disk.
- When using XML-mirroring YAML, flags like `--memory` and `--cpu` are ignored (a warning is printed).
- Swift warns if referenced disk/ISO files do not exist before defining the domain.

## Detecting which format

Swift auto-detects the format based on the top-level keys:

- Has `domain:` (as a map) → XML-mirroring VM format
- Has `network:` (as a map) → XML-mirroring network format
- Has `name:`, `disk:`, `memory:` → Simplified VM format
- Has `name:`, `cidr:`, `mode:` → Simplified network format

A top-level `domain` or `network` key with a string value (e.g. `domain: production`) does **not** trigger the XML-mirroring path.
